# Attendity Dashboard Colour and Static QR Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver dark-mode-safe dashboard colour semantics, secure static and rotating QR session modes, static-only PNG/PDF/print exports, and an accessible landing-page back-to-top control.

**Architecture:** Extend the existing shared UI primitives so colour rules propagate consistently, then add an explicit `qrMode` to the attendance domain with rotating as the backward-compatible default. Static credentials expire at the session closing time and never enter the rotation path; PDF export is authorised and generated by the API, while branded PNG and print output use the already-authorised static credential in the lecturer browser.

**Tech Stack:** React 19, TypeScript 5.9, Tailwind CSS 4, TanStack Query, Express 5, Zod 4, Mongoose 8, QRCode, PDFKit, Vitest, Node test runner, Testing Library.

## Global Constraints

- Preserve the established `apps/` and `packages/` monorepo architecture.
- Use strict TypeScript and shared types; do not introduce `any`.
- Use white and green as the primary brand colours, with mature university navy, academic gold, blue, rose, and violet accents.
- Never use gradient backgrounds.
- Preserve RBAC, tenant scoping, active-session validation, QR verification, GPS, face verification, registration checks, and duplicate prevention.
- Static QR is printable and downloadable only while its 5–180 minute session is open.
- Rotating QR refreshes every 30–120 seconds and must never expose print or download controls.
- Existing session records without `qrMode` behave as rotating sessions.
- Colour must not be the only carrier of meaning; retain labels, icons, percentages, badges, captions, and accessible names.
- Run only focused tests and affected-package type checks.
- This workspace has no `.git` directory; implementation checkpoints must list changed files instead of attempting commits.
